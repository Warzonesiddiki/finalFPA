=== Addon 2 Sec D (lines 592-610) ===
## SECTION D — FUNCTIONAL PRECISION (seed FRs for doc 02)

1. **Exception identity & re-run semantics.** Key = `rule_id + subject_key`. Re-running rules (after mapping/threshold changes) **never wipes workflow state**: open stays open, closed stays closed; re-flagged closed items show a "flagged again" badge, never auto-reopen. Full history per key.
2. **Aging & bulk operations.** Days-open per exception, aging buckets (0–7 / 8–30 / 31+), overdue highlight; multi-select bulk status/owner changes with one audit entry per item; owner auto-assign from cost-centre/account mapping, manual override always possible.
3. **Period status (Open/Closed).** Closing a period locks its actuals: void/re-import into a closed period requires an explicit, warned "reopen period" action, audit-logged.
4. **Re-import guard.** Identical file checksum → blocked with "already imported on <date>". Different checksum with overlapping vouchers → cross-batch duplicate report before commit.
5. **Control-total reconciliation.** Optional control-totals block in the actuals template; validation report compares file totals vs loaded totals vs (if provided) client control totals; variance fails the import or requires explicit acceptance — documented decision.
6. **Budget & forecast file validation.** Duplicate budget lines vs key; negative amounts; coverage matrix (which entity × account × period cells are missing, as %); sum-vs-approved-total check when provided; unmapped-account list.
7. **Three-way view + forecast accuracy.** Actual vs Budget vs Forecast in one view; for closed periods show Forecast vs Actual columns with signed error — formulas in doc 05, view in Analyze, feeds commentary.
8. **Rolling windows.** MTD, YTD, and TTM (trailing 12 periods) where data exists; window labels always visible so no ambiguous "period totals".
9. **One-off / exceptional item tagging.** PRD must decide explicitly: minimal v1 (tag actual rows → "adjusted" toggle views + AI mentions them) **or** park with rationale. Never left undecided.
10. **Rule effectiveness analytics.** Per rule: times raised, % closed as explained, average days to close, last threshold tuning — a tuning dashboard so the engine improves month over month without code changes.
11. **Global materiality setting** (e.g., % of budget or absolute floor) feeding default thresholds; per-rule overrides win.
12. **Export collision policy.** Existing file at target path → prompt (overwrite / keep-both with next `vN`); batch exports follow Addon 1 naming; never silent overwrite.
13. **Evidence bundle.** One click per exception → workbook/zip containing subject rows, relevant validation report, mapping version, and audit trail — ready to send to an accounting team.
14. **Scope decisions the PRD must settle (with defaults):** financial statements in v1 (default: P&L focus; balance sheet/cash flow parked); budget creation in-app (default: import-only); journal-category column (default: optional via mapping profile).

=== Addon 3 Sec C (lines 730-746) ===
## SECTION C — FEATURE PRECISION PART 2 (seed FRs for doc 02)

1. **AI Mapping Review Queue.** AI may only *propose* mappings: each suggestion carries source column, target field, confidence, and evidence (examples of previously accepted rows). States: `suggested → accepted | edited | rejected`. Accepted mappings apply to future imports; **never auto-applied in the same run**. Bulk accept/edit with audit trail; queue visible on every import using an unprofiled file.
2. **Mapping preview & profile auto-match.** Mapping screen shows the first N rows with detected types and sample values; saved profiles auto-suggest by header fingerprint when a file matches ≥ threshold of known headers; template files carry a **version stamp** and import warns on outdated templates.
3. **Commentary workflow.** Two levels: per-variance-line commentary and a per-period executive narrative (for slide 2). AI drafts are editable; every save versions text (author, timestamp, old→new). Commentary **locks when the pack is issued**; post-issue edits require a re-issue (C.4).
4. **Pack issuance register.** "Issue pack" freezes the underlying snapshot, increments pack version, records date + recipient list, and marks commentary locked. Re-issue creates a new version; issued packs are immutable; exports carry pack version (Addon 1 stamping).
5. **Data-quality score.** Composite 0–100 on the Check screen from weighted validation checks (formula + weights in doc 05) — always displayed **alongside** the individual failed checks so a single score can never mask a failure.
6. **Storage & health management.** CLI `doctor`: DB integrity check, disk space, project/schema version compatibility, WebView2 presence, data-dir permissions — with `--json`. In-app storage usage display; **archive-and-delete** flow (export raw archives to zip first, typed confirmation to delete); non-blocking backup reminder when a period is closed.
7. **Budget re-import semantics.** Re-importing a budget **replaces the selected budget version atomically** — never merges silently. A diff summary (old vs new totals by entity/period, with deltas) is shown before commit.
8. **Persistence & destructive actions.** Forms auto-save with visible "Saved" state; there is no global undo. Destructive actions (delete project, void batch, reopen period, archive-and-delete) require **typed confirmation naming the object** (e.g., type the period code).
9. **Home screen.** Open/recent project, current period + status, last import summary, KPI strip, quick actions (Import / Check / Generate pack), and health warnings (failed checks, stale derived results, storage low).
10. **No login in v1.** Single-user local app; privacy = OS user account; no in-app authentication — recorded as an explicit decision in docs 01/13 (multi-user auth backlogged).
11. **Import UX.** Drag-and-drop **and** file picker; after drop: fingerprint → profile match → preview → validation report → commit (all-or-nothing per Addon 1 P12).
12. **Display locale (project setting).** Date format (default `dd-mm-yyyy`), digit grouping — **Indian lakh/crore grouping option** (`₹ 1,23,456`) vs international, decimal places, negatives-in-parentheses toggle. Applies uniformly to app, Excel, and PPT (enforced by F.4 test).
