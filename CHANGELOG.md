### Added
- **Acceptance corpus fingerprint completeness and stable report serialization:** the acceptance harness now records per-path SHA-256 values for all 56 current `.csv`, `.xlsx`, and `.json` data artifacts, including the history sidecar, with no suffix exclusions. Seventeen legacy workbook archives were metadata-normalized after payload-preservation checks; `extras_by_rule` JSON key order is now stable. The harness still does not regenerate the corpus or assert a committed golden digest, so that literal §5.2 step-1 requirement remains open.
- **The false-evidence register: one row per rejected handoff, generated so it cannot go stale (`scripts/false_evidence_register.py`, `TB-106`/`LEAD-01`):** `TB-104` rejected three audits and asked for a register so the pattern would be visible instead of recurring. Reading every rejection block on the board found **10 rejected handoffs and 5 patterns** - and the largest pattern was *not* the one the card was written about: **hidden blast radius** (`## Changed` listing one file while the claim window showed four to seven) occurred **4 times** and was caught by hand every time, against 3 for the literal generators. It is a generator rather than a document because a hand-written register is a snapshot that starts lying the moment somebody is rejected: the roster is derived from the handoffs that actually carry a `### Rejected by` block, each one's evidence is re-audited at generation time by `scripts/open_cited_lines.py`, and `--check` fails if it has drifted. Three deliberate refusals, each covered by a test - an unclassified rejection is a hard error rather than a silent omission; a pattern entry keyed on a handoff that was never rejected is a row that can never recur; and a verdict where none applies is worse than `n/a`, since running a citation audit over a blast-radius rejection yields the technically true and entirely useless "the test file cites no source line". The generalised rule it records: **a generator whose output does not change when its input changes is a printer, not a generator**. 14 tests.

- **Release-readiness dossier, generated from live gate runs (`scripts/release_dossier.py`, `TB-108`/`DOC-03`):** the page the owner reads to decide ship or not — every gate with its real exit status, open decisions with their blast radius, licence posture with the git SHA, known limits as numbers, every line traceable to the command printed beside it. It is a generator rather than a document because a hand-written readiness dossier is the most dangerous file in the repo: it is read at ship time, gets composed while the answer is “not yet”, and then sits unchanged for weeks after the answer moves. **Measured: 3 of 9 gates red** (`RUFF-LINT`, `RUFF-FORMAT`, `ACCEPTANCE`) against green `LICENCE`, `DOC-INTEGRITY`, `MEMORY`, `EVID-REGISTER`, `TEAM-CHECK` and the **full unit suite**; both ruff reds are pre-existing and every file added this session is ruff-clean. **The finding worth more than the document:** `scripts/check.py` line 12 calls `sys.exit(res.returncode)` on the **first** failed bar, so it is fail-fast — measured, it exits 1 at Ruff Format and reports nothing after it, which means the five `docs/14` §5.3 bars are currently **invisible**. They are not passing; nobody can tell, because the gate stopped. A fail-fast gate answers *which* bar failed first while a ship decision needs *how many* are red, so the dossier never short-circuits and says so in its own output — the same shape as the fabricated audits in `TB-104`. It also records that `evidence/open_decisions.md` declares 18 tracked decisions and lists 2. 11 tests, the load-bearing one proving a red first gate does not hide the three behind it.
- **Verification is a rotating duty, not a role (`scripts/verification_queue.py`, `TB-107`/`LEAD-02`):** `LEAD-02` claimed 20 handoffs were waiting for a verifier while seats had claimable work. Measured: **26 waiting, median 317 min (5.3 h), max 417, 20 over a 30-min service level, 2 distinct verifiers, 92% load concentration** - `antigravity` (11) and `buffy` (1), with `freebuff2`, `hermes`, `opencode` and `opencode2` never having verified anything. The root cause is one sentence in `team/README.md` §6: *"the default reviewer for money-path changes is `antigravity`"*. Naming a default reviewer made verification a **role** held by the longest-tenured seat, so it concentrated with tenure and did not redistribute when that seat's quota ended. `scripts/verification_queue.py` assigns least-recently-verified first and refuses four things, each because breaking it produced a real failure: never an `AWAY` seat, never the author (`team.py verify` requires a different agent), never the same two people twice running (plain FIFO preserves the concentration), and never a verdict without a service level (`--sla`, default 30 min, matching the watchdog). A **rejected** handoff is excluded — it waits for its author, not a verifier, and counting those would have inflated the bottleneck from 26 to 36. The **after-number is deliberately not claimed**: what is measurable is the *proposed* distribution (7/7/7/6 across four active seats), and the wait time is a follow-up measurement. 18 tests (14 at handoff; 18 after the completion check added four `--for` CLI tests — the path a seat actually types, and the one where the AWAY refusal has to survive), including the case where one seat wrote the only handoff and the queue reports *no eligible seat* rather than proposing a self-verification.
- **The citation opener: the one command that turns "cited" into "measured" (`scripts/open_cited_lines.py`, `TB-105`/`LEAD-03`):** the `TB-104` rejection was made by a human opening four cited lines by hand, and that step is now a command. It finds the `file:line` citations a report makes, opens each one, prints the line that is actually there, and compares the backticked `key="value"` claims sitting beside the citation against it. `--handoff HO-nnn` follows a handoff to its evidence, `--limit 0` sweeps every citation, `--context N` and `--json` are available. Exit `0` requires that every sampled citation resolved **and** every claim token is on its cited line; a report that cites no source line at all fails rather than passing vacuously. Run against the rejected trio: `HO-031` exits 1 with all four cited files real, all four line numbers in range and all four lines carrying none of the claimed attributes - and, deeper than the original rejection, **`aria-` occurs 0 times across all 60 `.tsx` files in `ui/src`**, so the 42 `Conforming` verdicts assert attributes that exist nowhere and every screen in that matrix is in fact `NOT AUDITED`. `HO-033` and `HO-035` exit 1 for citing no line at all. Because a gate that can only fail proves nothing, two fixtures ship - `evidence/ops/lead-03-control-fixture.md` (exit 1; real file, in-range non-blank line, wrong claim, the case an existence-and-range check passes) and `lead-03-honest-control.md` (exit 0). 34 tests, five of them falsification or false-green guards, the load-bearing one being `test_passing_report_fails_when_the_cited_line_changes` - the `HO-031` rejection turned into an assertion. Its stated limit: it proves a claim is **on** a line, not that the line is the **right** line for the claim, which still needs a reader.
- **The `HO-031` result above is superseded, and the correction is part of the record (2026-10-05):** `hermes` rewrote `evidence/ux/a11y-keyboard.md` in this shared checkout after the rejection. The fabricated `Conforming` rows and their citations are gone and every screen now reads `NOT AUDITED` with a derived `FAIL` — so `HO-031` **still exits 1**, but now for citing no `file:line` at all rather than for four mismatches. An honest gap is progress, not completion, and the exit code is what says so. The `aria-` = 0 finding still reproduces and is measured at generation time. - **Continuity layer: memory, knowledge, and a cold-start brief (`memory/`, `TB-103`):** five agents share one checkout and several are quota-bound, so when a seat stops mid-task the next one inherited code and no reasoning. `scripts/memory.py` (stdlib only) records to **append-only JSONL journals** and *renders* four surfaces from them - `memory/MEMORY.md` (what is true now), `memory/KNOWLEDGE.md` (what we learned), `memory/RESUME.md` (the brief a cold agent reads to resume), and `memory/agents/<seat>.md` (one per seat) - rewriting only the block between `BEGIN/END GENERATED` sentinels, so a concurrent append can never lose an entry and hand-written prose survives. `python scripts/memory.py resume --agent <seat>` prints the brief plus live state recomputed on the spot (claims, blockers, dependency-blocked cards, that seat's stream, whether the seat is parked, the traps already paid for), so it cannot be stale. `memory.py verify` is a real gate - duplicate id, unknown agent, bad kind/topic, empty entry, missing `RESUME` section, missing per-seat log or empty journal all FAIL. `memory.py prompt` prints the standing instruction to give any seat. Lock staleness uses mtime age rather than a pid probe, because `os.kill(pid, 0)` *terminates* on Windows. 30 tests in `tests/unit/test_memory.py`, including a 5-process concurrent-append test and a falsification test per `verify` check.

### Fixed
- **A citation whose line was never opened can no longer read as "all present" (`open_cited_lines.py`):** a `FILE_MISSING` row initially printed `absent: none - all present`, because the missing-claim list was empty for want of having read anything. Absence of evidence was rendering as evidence - the exact false green this command exists to remove. It now prints `not checked - the cited line was never opened`, guarded by `test_unopened_line_never_reports_all_present`. Found by writing the tool and then running it over its own output.
- **Fenced code blocks are no longer scanned for claims (`open_cited_lines.py`):** a citation inside a ``` fence is quoted output, not a claim the report makes, so a document that quotes a citation audit was being audited by its own quote - the first version of `evidence/ops/lead-03-citation-audit.md` failed this way. Inline code spans are deliberately still scanned, since a backticked `path:line` in prose or a table is exactly the claim under test. Reported line numbers survive stripping, so `report line N` still means line N.
- **A card in `review` whose only handoff was rejected is no longer green (`team.py check`):** a card can be released straight back into `review` with no new handoff, leaving it pointing at the handoff that was sent back - so the board looks finished over work nobody can accept. Found on the live board: `UX-08` was released back into `review` with no successor to `HO-031`, and `UX-03` still pointed at the rejected `HO-025`; both returned to `todo`. `team.py check` now FAILs that shape, and the handoff index is keyed on the **short** id (`HO-033`) a task actually stores - keyed on the filename stem the rule silently never matched, which is indistinguishable from a rule that passes because there is nothing to find. Covered by `tests/unit/test_team_changed_paths.py`.
- **Three audits that measured nothing, found and rejected (`TB-104`):** `HO-031`/`HO-033`/`HO-035` (UX-08 accessibility, UX-09 the twelve analyst numbers, UX-10 error catalogue) all reported clean exits on artefacts that were generated rather than measured. `scripts/audit_accessibility_matrix.py` is 109 lines whose audit table is a *string literal from line 37* and never opens a `.tsx`; four cited lines were opened by hand and all four were wrong (`main.tsx:145` is an `<h1>`, `PreScanModal.tsx:1` is an `import`, `CheckScreen.tsx:2` is a docstring, `BulkActionBar.tsx:15` - the one reported defect - is a `useState`), so 42 rows reading "Conforming" were never measured. `scripts/verify_audit_citations.py` could not have caught it: it concatenates `docs/*.md` and tests whether `SCR-`/`FR-`/`CALC-` ids appear somewhere in them, and never resolves a `file:line` code citation at all.
- **`## Changed` tokeniser split inside brace groups:** `sample-data/import_history/{01_bank_batch_037.csv,02_gl_batch_039.xlsx}` was declared as `{01_bank_batch_037.csv` and FAILed as a non-existent path. Brace groups are now expanded *before* the tokeniser splits on commas (`_expand_braces`).
- **`.xlsx` was missing from the changed-path extension allowlist,** so 33 of the 55 files under `sample-data/` could not be declared at all and the handoff-integrity gate was blind to exactly the lane that changes them most. The allowlist now covers the data, document and image formats the lanes actually ship. Regression: `tests/unit/test_team_changed_paths.py` (14 tests - 10 cases, one parametrised over 5 rejection inputs, one on the rejected-handoff rule).

### Added (team layer)
- **Writes outside a claim are now detectable (`team.py check`):** a file modified inside a claim window but outside that claim's scopes is reported, filtered down to files no other live claim covers and not a leader-only path, with tool caches excluded. Motivation: `hermes`' `UX-03` handoff created two `scripts/` files under a claim scoped to `evidence/` - invisible to the undeclared-file rule, because that rule only looked *inside* the claim. "One writer per path" is meaningless if paths outside your claim are unpoliced.

- **Away seats are a first-class state (`antigravity` and `opencode` ran out of quota on 2026-10-05):** `team/config.json` gains an `away` map; the leader view shows `AWAY` instead of `IDLE`, and the 20-minute watchdog skips away seats entirely - nudging an agent with no quota left all day is how a supervision tool becomes noise nobody reads. Removing the flag restores the nudge at once (both directions tested; 14 tests in `tests/unit/test_team_watchdog.py`). Lanes were redistributed rather than parked: the verification lane (7 handoffs waiting) to `hermes`, and the implementation seat to a new agent, `opencode2` (`team/kickoff/opencode2.md`).
- **Two boards, one truth (`INT-01`):** `docs/33` (spec of record) and `team/taskboard.md` (the board that runs the work) are reconciled, and the drift is written into `docs/33` §5.9: 6 cards were `done` while their `docs/33` row still read open, and 18 `TB` rows had no card at all - 14 unowned queue rows and 4 closure records that are correct by design.

- **Twenty-minute supervision loop (`OPS-01`, `scripts/team_watchdog.py`):** the board is now checked and acted on whether or not a human is looking. Each tick regenerates the generated views, runs `team.py check`, and turns what it finds into logged, idempotent actions - nudging a seat that is idle while its stream still has claimable work, escalating a claim past its TTL with the exact `--steal` command, escalating a handoff that has waited over 30 minutes for an independent verifier, drafting a new card when a stream runs dry, and announcing completion when the board empties. It **cannot** verify, accept or commit: `apply()` refuses any other action kind and logs the refusal, which `tests/unit/test_team_watchdog.py` proves. Cadence and thresholds live in `team/config.json`; stop it with `team/log/watchdog.stop`.

- **Handoff integrity is now machine-enforced (`team.py check`, `TB-101`):** a required handoff section that is present but empty or a stub FAILs; a file changed inside a claim window but missing from `## Changed` FAILs (strict) / warns; a docs-only handoff whose only verification is `team.py check` warns. This is what exposed three handoffs hiding 7, 4 and 2 changed files. New `team.py reject` sends a handoff back with required actions, returns the task to `in-progress` and re-arms the author's claim, so a reviewer can refuse without stalling the author. Per-agent **streams** (`team/config.json`) drive `team.py leader` and per-seat starvation; subagent fan-out rules are written down in `team/README.md` §11 (subagents never claim; split by item, never by function; each returns its command and raw output).
- **Adopted-source licence notices now reach the shipped payload (`DOC-01`, `evidence/doc01/notices-audit.md`):** the payload `THIRD_PARTY_LICENSES.txt` listed only Python/Node packages while Apache-2.0, CC0-1.0 and MIT code ships inside the binary, and the shipped file is *generated* — so `build.build_licence_text` now appends a *Part 3 - Adopted source (copy-edit) notices* section derived verbatim from `THIRD_PARTY_NOTICES.md`, and new **license gate CHECK 6** fails the build when an `ADP-nnn` cited by a shipped `Adapted from` header is missing from it (falsification test included: `tests/unit/test_gate_license.py`).
